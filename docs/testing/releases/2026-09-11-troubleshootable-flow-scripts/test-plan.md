# Troubleshootable Flow scripts: test plan

- Change/PR: every managed Flow's `Scripts/run_flow.py` is regenerated on every save and after every application update, never blocked by a hand-edited copy (the edit is archived under `Scripts/versions`), and is plain Python whose module sections are copied verbatim from `app/<module>.py` with real line numbers in tracebacks, echoed progress and full tracebacks on failure. The execution-core fingerprint no longer gates recorded runs or script generation; it is recorded as evidence only.
- Code baseline: `494cc156930941738c1eb40ab351327e2c62e2dd` (`main` at PR #112).
- Related report: [test-report.md](test-report.md)
- Intended environments: checkout-owned Python 3.13 with the locked dependencies (`tools/check.ps1 -Mode Setup` on Windows; `requirements-ci.lock` in a Linux venv for this task); synthetic local-file and recorded fixtures; bundled Chromium for the portable pipeline case. No live portal, Outlook, SQL or work-PC checks are in scope.

## Prerequisites and test data

Use an isolated database and managed Flow root (`DG_DB_PATH`, `DG_TEST_RUN_ROOT`, `DG_BROWSER_PROFILE_ROOT`, or the verifier's per-run directory). Fixtures are fictional: a two-line CSV local-file Flow (`tests/test_flow_standalone.py::local_job`) and the synthetic recorded portal Flow (`tests/test_flow_recordings.py::draft_job`, `activate_test_revision`). Do not point any case at a production Flow folder or SQL target.

## Acceptance and cleanup

Accept when every S-case passes locally on the tested revision and final-head CI is green and recorded in the PR. After deploying, every managed Flow regenerates its script once at startup (one new `Scripts/versions/run_flow-<hash>.py` each) because the embedded execution source now keeps comments; that is expected. Hand-edited scripts are never lost: look for `run_flow-*-edited-*.py` under `Scripts/versions`. Rollback is a normal `main` redeploy; scripts regenerate to the previous format at the next startup, and archived edits remain in place. Test folders and databases are verifier-owned scratch data and may be deleted.
